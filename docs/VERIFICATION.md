## 에뮬레이터 확인 필요

1682dp 창에서 홈·운행 선택·비용·인원·결과 화면의 문구와 QR 판독을 확인했습니다. 아래 항목은 단위 테스트와 빌드로만 확인했습니다.

- 이름 입력란 오류 표시: 대소문자나 앞뒤 공백만 다른 이름도 중복으로 표시.
- 계산 기준 변경 폼의 단가 출처 안내: 단가를 그대로 두면 `출처 · 기준일`, 직접 입력하면 `직접 입력한 단가로 계산해요.`
- 841dp 창과 글꼴 130%에서 바뀐 문구의 줄바꿈.

계산 검증에는 3/4/5인 금액 전수 사례, 300개 무작위 부분 참여 정산, 비용별/전체 합계 일치를 포함합니다. core와 QR 구현 테스트는 Android/지도 SDK 없이 일반 JVM에서 실행합니다.

구조 검사는 모듈 역참조, UI의 구체 데이터/지도/QR 구현 참조, 어댑터 외부 SDK 의존성을 차단합니다. UI→Mock과 core→지도 API 역참조를 의도적으로 넣으면 검사가 실패하는 것을 확인했습니다.

## 에뮬레이터에서 확인한 MVP 흐름

- 홈 → 새 정산 → 11월 1/2일 다중 선택 → 4개/415km/56,440원.
- 왼쪽 운행 목록과 오른쪽 실제 도로 지도, 전체 경로 맞춤·확대 버튼 확인.
- 기본 4명 각 14,110원, 3명은 18,814/18,813/18,813원, 5명은 각 11,288원. 결과 총합과 차액 0원 확인.
- 새 QR 어댑터를 통해 화면에 그려진 QR 스크린샷을 다시 판독해 한글 요약·총 56,440원·1인 14,110원·예시 단가 고지가 정확히 복원됨을 확인.
- 비동기 저장 후 실제 SharedPreferences JSON의 4개 선택/4명을 확인하고 강제 종료·재실행 → 이어서 하기 → 56,440원 복원.
- 주간/야간 지도 전환, D·30km/h에서 지도/조작 제거 및 시스템 차단, P·0km/h 복귀 후 선택/지도 복원.
- 검증용 초안을 마지막으로 확인한 원본 JSON과 전체 일치하도록 복원. 앱은 홈, P·0km/h, 주간이며 에뮬레이터 실행 상태 유지.

Lint는 앱 오류 0개/경고 16개(도구·라이브러리·target 버전 권장), 나머지 Android 구현 모듈은 이슈 없음입니다. 검증 스크린샷과 로그는 Git에서 제외한 `.local/baseline-qa/`, `.local/brand-qa-20261104/`에 있습니다.

## 디자인 검증

- 홈·운행·비용/인원·결과·QR의 실제 에뮬레이터 스크린샷을 확인했습니다. 자동차·표정·아이콘은 자체 Compose Canvas이며 런처는 같은 자동차의 VectorDrawable입니다.
- 바뀐 UI에서 3/4/5명 부담금과 차액 0원, 개별 운행 해제/재선택에 따른 317/415km 갱신을 확인했습니다.
- 841×1210dp 창, 야간, 글꼴 130%를 함께 적용했습니다. 실제 앱 Configuration의 `fontScale=1.3` 반영을 확인하고 한 열 배치·경로 펼침·단가 폼과 키보드 위 취소/적용 버튼을 확인했습니다.
- 넓은 주간 화면과 좁은 야간/130% 화면에 실제 표시된 QR 모두 스크린샷에서 판독했습니다. 한글 요약·총액 56,440원·1인 14,110원이 일치합니다. 휴대폰 카메라 실기기 검증은 별도입니다.
- 단가 폼에 저장 전 1,900원을 입력한 채 D·30km/h로 전환해 입력/적용 조작이 사라짐을 확인했습니다. P·0km/h 복귀 시 저장 전 입력이 복원되고, 취소 후 기존 56,440원을 유지했습니다.
- 초록색 주요 버튼·눌림 상태·선택 칩의 주야간 글자 대비 조합은 `PleosContrastTest`에서 검사합니다.

## 실행과 검증 범위

개발 APK는 `app/build/outputs/apk/debug/app-debug.apk`입니다. GitHub Actions에 같은 검사 스크립트를 구성했으며 원격 CI 결과는 GitHub 업로드 후 확인해야 합니다. CI 단위 테스트는 실차/UI 검증을 대체하지 않습니다.

실제 운행 기록/순정 지도 내장/차량 기본값 자동 조회/실시간 평균가는 미연동입니다. 지도 배경은 실제 도로 지도이며 운행 경로 좌표·거리·차량·가격은 Mock 시연 데이터입니다. 지원 API·권한 및 실차 동작은 별도 검증이 필요합니다.

MVP 범위 결정 전 UI·SDK 실험 기록은 [실험 기록](history/PRE_MVP_VERIFICATION.md), 순정 SDK 조사 결과는 [NaviHelper 조사](NAVI_SDK_FINDINGS.md)에 보존합니다.
