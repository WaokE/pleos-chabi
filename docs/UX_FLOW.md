# 차비 MVP 0.6 — 운행 선택 중심 UX

2026-11-04. 앱은 홈과 3개 순차 화면으로 구성합니다.

## 사용자의 필수 결정

1. **홈**: 초안이 없으면 `운행 고르기`, 있으면 `이어서 하기`를 먼저 표시합니다. 운행·비용·인원과 마지막 단계가 함께 저장되어 앱을 다시 열어도 하던 화면으로 돌아갑니다. `새 정산`이 기존 초안을 대체할 때는 확인합니다.
2. **운행 선택**: 날짜별/개별 선택, 목록 필터(전체 운행·선택한 운행), 거리와 예상 비용 확인. 특정 시연 날짜에 맞춘 필터는 두지 않습니다. 선택만으로 다음 화면으로 이동하지 않고 `운행 N개로 정산하기`로 확정합니다.
3. **비용·인원 확인**: 운전자 포함 인원을 선택합니다. 기본값으로 계산한 비용과 1인 부담금이 즉시 반영됩니다. 이름을 입력할 필요는 없습니다.
4. **결과**: 1인 부담금, 사람별 배분과 총합을 확인하고 QR로 휴대폰에 전달합니다.

현재 기본 시연은 이름·금액 입력 없이 4개 운행 415km → 56,440원 → 4명 각 14,110원까지 완료됩니다. 1분 내 완료는 제품 검증 목표이며 사용자 연구로 측정한 결과는 아닙니다.

## 선택 기능

- 연료 종류, 적용 연비·전비, 단가는 `기준 변경`에서 수정합니다. 취소하면 수정 전 값을 유지하며, 검증에 성공한 입력만 적용합니다.
- 통행료·주차비는 비용 확인 화면의 접힌 선택 영역에 있습니다. 기타 지출·식비 등록 메뉴와 별도 참가자 탭은 두지 않습니다.
- 참가자 이름은 접힌 선택 기능입니다. 기본 인원은 운전자 포함 4명, 조절 범위는 1~20명입니다.
- 초안에 저장된 기타 지출과 부분 참여 비용은 유지합니다. 접힌 비용 요약에 금액을 포함하고, 펼치면 수정·삭제 및 참여자 재지정이 가능합니다. 인원 축소로 참여 집합이 비면 결과 생성을 막습니다.
- 결과의 계산 내역은 기본으로 접고 필요할 때 펼칩니다. 각 비용을 나누고 남은 원을 배분한 경우에만 등록 순서대로 1원씩 더했다는 안내를 표시합니다.

## 운행 경로 미리보기

`Trip.route`를 MapLibre Native 지도에 겹쳐 표시합니다. 큰 창에서는 왼쪽 운행 목록과 오른쪽 지도를 함께 표시하고, 작은 창에서는 목록 안의 펼침 영역을 사용합니다. 초록색은 정산에 포함한 운행이며 최근 확인한 선택 경로는 굵게 표시합니다. 지도 경로를 누르면 확인 구간만 바뀌고 정산 포함 여부는 바뀌지 않습니다. 선택한 모든 경로가 화면에 들어오도록 범위를 맞추며 확대·축소·전체 경로 버튼을 제공합니다.

배경은 OpenFreeMap의 실제 도로·지명 지도입니다. 현재 운행 좌표는 도로망을 따라 생성한 **예시 경로**이며 실제 주행 기록이 아닙니다. 지도 로딩·실패/재시도와 출처 안내를 제공합니다. 누락·손상된 좌표를 출발/도착 지명 사이 직선으로 대체하지 않습니다. [지도 상세](EMBEDDED_MAP.md)

외부 순정 내비로 전환하는 NaviHelper UI와 의존성은 포함하지 않습니다. 공식 NaviHelper의 화면 요청 API를 앱 내부 MapView나 과거 궤적 조회 API로 간주하지 않습니다.

## 차량과 단가

`DriveDefaultsRepository`를 추가하고 Application에서 `MockDriveDefaultsRepository`를 주입합니다. 기존 `TripRepository`와 독립적으로 차량·단가 공급원을 교체할 수 있습니다.

- 예시 기본 차량은 휘발유, 적용 연비 12.5km/L, 단가 1,700원/L입니다. 경유·LPG·전기도 시연용 프리셋을 제공합니다.
- 모든 기준 단가는 **시연용 예시**입니다. 실제 SDK의 차량 정보나 오피넷의 현재 평균가로 표시하지 않습니다. 서버와 API 키를 임의로 도입하지 않았습니다.
- 단가는 소수 셋째 자리까지 Decimal로 보존하고 최종 원화 비용만 한 번 반올림합니다. 직접 변경한 단가의 출처와 기준일을 초안에 저장합니다. 재실행이나 결과 진입 시 최신 기본값으로 덮어쓰지 않습니다. QR 요약에도 적용 단가의 출처를 포함합니다.
- 실제 평균가 연결 시에는 가격 종류·기준일·지역·단위와 실패 시 대체 정책을 확정해야 합니다. 전기차는 사업자·출력·회원 요금 차이를 고려해야 합니다.
- 차량 연료 종류 자동 판별은 AAOS `INFO_FUEL_TYPE`의 Pleos 접근 가능 여부를 확인한 뒤 구현할 후보입니다. 연료 종류 복수 반환을 임의로 단일 에너지로 바꾸지 않습니다.

## 휴대폰 전달

ZXing Core 3.5.3으로 UTF-8 텍스트 QR을 기기 안에서 생성합니다. 서버 업로드·네트워크·계정 없이 운행 수·거리·비용·개인별 부담금·적용 단가의 요약을 전달합니다. GPS 좌표나 상세 시간 기록은 QR에 넣지 않습니다.

텍스트 QR을 지원하는 휴대폰 카메라나 스캐너에서 요약을 읽을 수 있습니다. 휴대폰 기종별 카메라 동작과 메신저 전달 경험은 별도로 확인해야 합니다. QR 생성에 실패하면 같은 화면에서 다시 만들 수 있습니다.

## 차량 UI와 안전

[Pleos UI 가이드](PLEOS_UI_GUIDE.md)의 타입·색상·터치 크기를 유지합니다. 가로/세로 창에서 내용이 줄바꿈·스크롤되며, 키보드와 팝업 동작 영역을 분리합니다. 단계 변경 시 키보드를 닫습니다.

정산 전체에 기존 `CarUxRestrictionsManager` 기반 제한을 유지합니다. 주행 제한·상태 미확인에서는 조작을 허용하지 않습니다. 정차 복귀 시 작성 중인 비용·계산 기준 폼을 보존합니다.
