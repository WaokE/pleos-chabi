# 차비 MVP 0.6 — 운행 선택 중심 UX

앱은 홈과 3개 순차 화면으로 구성합니다.

## 사용자의 필수 결정

1. **홈** · 불러온 운행의 개수·날짜 범위·총거리를 표시합니다. 초안이 없으면 `운행 고르기`, 있으면 `이어서 하기`를 표시합니다. `이어서 하기`는 저장된 마지막 유효 단계로 이동합니다. `새 정산`으로 초안을 바꿀 때는 확인을 받습니다.
2. **운행 선택** · 전체 운행과 선택한 운행을 전환하고, 날짜별 또는 개별로 고릅니다. 하단에서 거리와 예상 비용을 확인한 후 `운행 N개로 정산하기`를 눌러 진행합니다.
3. **비용·인원 확인** · 운전자 포함 인원을 선택하면 비용과 1인 부담금이 갱신됩니다. 기본 흐름은 이름 입력 없이 `결과 보기`까지 진행할 수 있습니다.
4. **결과** · 예상 총액과 사람별 부담금을 확인합니다. 결과 카드에서 카카오페이 링크 QR을 띄울 수 있고, 분담 목록 아래에서 카드 뽑기를 열 수 있습니다.

## 선택 기능

- 연료 종류, 적용 연비·전비, 단가는 `기준 변경`에서 수정합니다. 취소하면 수정 전 값을 유지하며, 검증에 성공한 입력만 적용합니다.
- 통행료·주차비는 비용 확인 화면의 접힌 선택 영역에 있습니다. 기타 지출·식비 등록 메뉴와 별도 참가자 탭은 두지 않습니다.
- 참가자 이름은 접힌 선택 기능입니다. 기본 인원은 운전자 포함 4명, 조절 범위는 1~20명입니다.
- 초안에 저장된 기타 지출과 부분 참여 비용은 유지합니다. 접힌 비용 요약에 금액을 포함하고, 펼치면 수정·삭제 및 참여자 재지정이 가능합니다. 인원 축소로 참여 집합이 비면 결과 생성을 막습니다.
- 각 비용을 나누고 남은 원을 배분한 경우 결과 화면에서 등록 순서대로 1원씩 더했다는 안내를 표시합니다.
- 두 명 이상이고 총액이 있으면 결과에서 `카드 뽑기로 한 명이 내기`를 선택할 수 있습니다. 이름을 입력하지 않고 돌아가며 한 장씩 뒤집고, 각 카드가 뒤집히는 순간 `당첨` 또는 `통과`를 확인합니다. 당첨자가 나오면 남은 카드가 함께 뒤집히고 폭죽 애니메이션이 재생됩니다. `이 결과로 정산하기`를 누르면 당첨자의 전액 부담을 결과와 초안에 반영합니다. 정산 입력을 바꾸거나 기본 분담으로 돌아가면 카드 결과가 해제됩니다.

## 운행 경로 미리보기

`Trip.route`를 MapLibre Native 지도에 겹쳐 표시합니다. 큰 창에서는 왼쪽 운행 목록과 오른쪽 지도를 함께 표시하고, 작은 창에서는 목록 안의 펼침 영역을 사용합니다. 선택한 경로는 테마 강조색으로, 확인 중인 선택 경로는 더 굵게 표시합니다. 지도 경로를 누르면 확인할 구간을 바꿀 수 있습니다. 선택 경로에 카메라 범위를 맞추고 확대·축소·전체 경로 버튼을 제공합니다.

배경은 OpenFreeMap의 실제 도로·지명 지도입니다. 현재 운행 좌표는 도로망을 따라 생성한 **예시 경로**입니다. 지도 로딩과 실패 시 재시도 안내를 제공하며, 출처와 라이선스 주소는 지도 왼쪽 아래에 표시합니다. [지도 상세](EMBEDDED_MAP.md)

외부 순정 내비로 전환하는 NaviHelper UI와 의존성은 포함하지 않습니다. 공식 NaviHelper의 화면 요청 API를 앱 내부 MapView나 과거 궤적 조회 API로 간주하지 않습니다.

## 차량과 단가

`DriveDefaultsRepository`를 추가하고 Application에서 `MockDriveDefaultsRepository`를 주입합니다. 기존 `TripRepository`와 독립적으로 차량·단가 공급원을 교체할 수 있습니다.

- 예시 기본 차량은 휘발유, 적용 연비 12.5km/L, 단가 1,700원/L입니다. 경유·LPG·전기도 시연용 프리셋을 제공합니다.
- 모든 기준 단가는 **시연용 예시**입니다. 실제 SDK의 차량 정보나 오피넷의 현재 평균가로 표시하지 않습니다. 서버와 API 키를 임의로 도입하지 않았습니다.
- 단가는 소수 셋째 자리까지 Decimal로 보존하고 최종 원화 비용만 한 번 반올림합니다. 직접 변경한 단가의 출처와 기준일을 초안에 저장합니다. 재실행이나 결과 진입 시 최신 기본값으로 덮어쓰지 않습니다.
- 실제 평균가 연결 시에는 가격 종류·기준일·지역·단위와 실패 시 대체 정책을 확정해야 합니다. 전기차는 사업자·출력·회원 요금 차이를 고려해야 합니다.
- 차량 연료 종류 자동 판별은 AAOS `INFO_FUEL_TYPE`의 Pleos 접근 가능 여부를 확인한 뒤 구현할 후보입니다. 연료 종류 복수 반환을 임의로 단일 에너지로 바꾸지 않습니다.

## 카카오페이 1/N 정산

결과 화면의 공식 버튼을 누르면 발급된 정산 링크의 QR이 표시됩니다. 버튼은 공식 이미지 비율을 유지하며 창의 가용 폭에 맞춰 최대 400dp로 표시합니다. 휴대폰 카메라로 스캔하고 카카오페이에서 정산 금액을 직접 입력합니다. QR에는 링크만 들어갑니다. [카카오페이 정산하기 가이드](https://developers.kakaopay.com/docs/moneytransfer/splitbills.link/splitbills-link-hands-on)

## 차량 UI와 안전

[Pleos UI 가이드](PLEOS_UI_GUIDE.md)의 타입과 터치 크기를 적용합니다. 시스템의 자동·라이트·다크 모드와 사용 가능한 그래파이트·팝 색상 토큰을 따릅니다. 다음 단계는 오른쪽에서, 이전 단계는 왼쪽에서 나타나며 모달에는 페이드 전환을 적용합니다. 단계 변경 시 키보드를 닫습니다.

정산 전체에 기존 `CarUxRestrictionsManager` 기반 제한을 유지합니다. 주행 제한·상태 미확인에서는 조작을 허용하지 않습니다. 정차 복귀 시 작성 중인 비용·계산 기준 폼을 보존합니다.
